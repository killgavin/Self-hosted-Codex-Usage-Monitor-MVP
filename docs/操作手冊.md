# Self-hosted Codex Usage Monitor 操作手冊

## 先選擇要操作的流程

| 目標 | 請操作 |
|---|---|
| 在瀏覽器查看 Codex 帳號與 rate limits | [A. 網頁儀表板](#a-網頁儀表板) |
| 將加密快照更新到 Google Drive，或驗證 HTTPS 檔案 | [B. Go Collector V1](#b-go-collector-v1) |

這兩套流程互相獨立。網頁儀表板不會使用 Collector 的 Google Drive 檔案；Collector 不會讀取 Dashboard 快取。

---

## A. 網頁儀表板

### A-1. 前置條件

- 已安裝 Docker Engine 與 Docker Compose v2。
- 執行主機能連線至官方 Codex 登入服務。
- 若要遠端使用，已準備 HTTPS、私人網路或具存取控制的反向代理。不要直接把服務公開到 Internet。

完整網路與部署設定請參考[部署指南](deployment.md)。

### A-2. 建置並啟動

在 Repository 根目錄執行：

```sh
docker compose up -d --build
docker compose ps
```

預設開啟 <http://127.0.0.1:8080/>。檢查監控 HTTP 服務：

```sh
curl --fail http://127.0.0.1:8080/health
```

預期回應為 `{"status":"ok"}`。這只確認監控 HTTP 服務可回應；Codex App Server 狀態要看 Dashboard 的連線狀態。

### A-3. 官方登入

1. 在瀏覽器開啟 Dashboard，等待頁面檢查登入狀態。
2. 選擇 **Log in**。
3. 在畫面上選擇 **Open verification page**，前往官方驗證頁。
4. 輸入 Dashboard 顯示的 **User code**，並依官方頁面完成登入與授權。
5. 回到 Dashboard 等待登入完成，頁面會載入帳號摘要與 rate limits。
6. 若不想繼續尚未完成的登入，選 **Cancel**；完成登入後可用 **Log out** 登出。

瀏覽器只會向同一個監控服務呼叫登入 API。不要在 Dashboard 或瀏覽器開發者工具輸入 OpenAI 憑證或自行複製 credential 檔。

### A-4. 閱讀畫面

- **Connection status**：`Connected` 表示頁面資料 API 已成功回應；`Connection failed` 表示此次取資料失敗。若 Codex 執行階段啟動失敗，服務可能仍可開啟，但狀態會呈現降級或取資料失敗。
- **Account**：查看 `Authenticated`、`Auth mode` 與 `Plan`。
- **Reset credits**：查看 `Available` 數量。這是唯讀資料，Dashboard 不會消耗 credit。
- **Rate limits**：每張卡片檢視 limit 名稱、Primary／Secondary 使用與剩餘百分比、剩餘量進度條及 reset 時間。資料有多種 limit 時會逐張顯示。
- **Last updated**：本次頁面取得資料的本機時間。Rate-limit 結果預設在伺服器記憶體快取 60 秒。

目前頁面沒有獨立的重新整理按鈕；需要重新取資料時重新載入頁面。快取有效期間內，rate-limit 資料仍可能沿用前一次結果。

### A-5. 停止、重啟與更新

```sh
docker compose stop       # 停止，保留容器與資料
docker compose start      # 啟動已停止的容器
docker compose restart    # 重啟服務
docker compose up -d --build  # 重建並啟動
docker compose down       # 移除容器與網路，保留具名 volume
```

Codex 設定與登入狀態保存在 `codex_monitor_home` 具名 volume。**不要使用 `docker compose down -v`**，除非確定要刪除該 volume 及其中的登入狀態與設定。

### A-6. 常見問題

| 現象 | 建議處理 |
|---|---|
| 瀏覽器無法連線 | 查看 `docker compose ps`；確認 `CODEX_MONITOR_PORT`、主機防火牆及是否有其他服務占用連接埠。 |
| 資料 API 回傳 `401` | 先透過 Dashboard 完成官方 Codex 登入；此 API 以伺服器端登入狀態為條件。 |
| `/health` 正常但 Dashboard 無法讀取資料 | `/health` 只代表 HTTP 服務回應。檢查官方登入狀態、Codex CLI 可用性與 `docker compose logs --tail=100 monitor`。 |
| 登入狀態在重啟後遺失 | 確認一直使用同一個 `CODEX_MONITOR_HOME_VOLUME`；不要刪除 volume 作為排錯步驟。 |
| 需要從外部網路連線 | 依[部署指南](deployment.md)設定 HTTPS 與 Access 控制；不要直接公開監控服務。 |

排錯時不要把 `.env`、OAuth 資料、憑證內容或含有私人設定的完整 log 貼到公開位置。

## B. Go Collector V1

### B-1. 前置條件

- Windows x64。
- Go 1.24.0 或更新版本。
- 執行 Collector 的 Windows 使用者已使用官方 Codex CLI 登入。
- Google Drive API 已啟用，並備妥 OAuth **Desktop app** Client ID 與 Client Secret。
- 已建立要更新的 Google Drive Binary 檔案，並取得固定 File ID。
- 已準備 AES-128 Key（16 bytes，以 32 個 Hex 字元表示）。第一次發布前，也須決定 HTTPS Client 是否要匿名下載該檔案。

Collector 每次啟動只做一輪讀取與發布，沒有內建常駐模式或排程器。執行位置為 `collector/`。

### B-2. 準備設定

Go 程式**不會自動載入 `.env`**。環境變數須設定在啟動 Collector 的同一個 PowerShell session，或由受控的環境變數／秘密管理工具注入。

先在 PowerShell 切換目錄並填入非秘密設定：

```powershell
Set-Location '<Repository 路徑>\collector'
$env:CODEX_MONITOR_DRIVE_FILE_ID = '<固定 Google Drive File ID>'
$env:CODEX_MONITOR_GOOGLE_CLIENT_ID = '<OAuth Desktop App Client ID>'
$env:CODEX_MONITOR_GOOGLE_TOKEN_FILE = Join-Path $env:LOCALAPPDATA 'CodexUsageMonitor-google-token.json'
$env:CODEX_MONITOR_CODEX_PATH = 'codex'
```

若 token 檔案改放其他路徑，請先建立其父目錄，並放在 Repository 外、由適當 Windows ACL 保護的位置。程式會在首次授權後將 token 寫入該檔，後續 access token 更新時也會更新本機檔案。

在安全的環境設定流程中，載入既有 AES Key 與 Google Client Secret。若沒有秘密管理工具，可在目前 PowerShell 視窗以遮蔽輸入取得 Client Secret：

```powershell
$secretInput = Read-Host 'Google OAuth Client Secret' -AsSecureString
$env:CODEX_MONITOR_GOOGLE_CLIENT_SECRET = [System.Net.NetworkCredential]::new('', $secretInput).Password
```

此輸入方式可避免 Secret 回顯在畫面或出現在命令本文；Collector 必須從環境變數讀取 Secret，因此執行期間它仍存在於目前程序環境。完成操作後請關閉這個 PowerShell 視窗，或清除該環境變數。

第一次建立環境時可產生 AES Key；只在建立新 Key 時執行。請將產生的環境變數值安全保存於 Repository 外的秘密管理位置，日後 Collector 與 HTTPS Client 必須載入同一把 Key。不要列印 Key、貼進共享命令紀錄或提交到 Git。

```powershell
$keyBytes = [byte[]]::new(16)
[Security.Cryptography.RandomNumberGenerator]::Fill($keyBytes)
$env:CODEX_MONITOR_AES_KEY = [Convert]::ToHexString($keyBytes)
```

若使用 Windows PowerShell 的使用者範圍 DPAPI 保存 Key，可在第一次產生後將它加密存到 `%LOCALAPPDATA%`。未指定自訂 Key 時，PowerShell 使用 Windows DPAPI；依 Windows 的資料保護範圍，通常需由相同使用者在同一部電腦還原。詳見 [PowerShell SecureString 說明](https://learn.microsoft.com/powershell/module/microsoft.powershell.security/convertto-securestring) 與 [Windows DPAPI 說明](https://learn.microsoft.com/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata)。確認這是新 Key 後再執行，`-NoClobber` 會避免覆寫既有檔案：

```powershell
$keyFile = Join-Path $env:LOCALAPPDATA 'CodexUsageMonitor-aes-key.dpapi'
$secureKey = ConvertTo-SecureString $env:CODEX_MONITOR_AES_KEY -AsPlainText -Force
ConvertFrom-SecureString $secureKey | Set-Content -LiteralPath $keyFile -NoNewline -NoClobber
```

後續 PowerShell session 可從同一 Windows 使用者的檔案載入：

```powershell
$keyFile = Join-Path $env:LOCALAPPDATA 'CodexUsageMonitor-aes-key.dpapi'
$secureKey = ConvertTo-SecureString ([IO.File]::ReadAllText($keyFile))
$env:CODEX_MONITOR_AES_KEY = [System.Net.NetworkCredential]::new('', $secureKey).Password
```

若使用自己的秘密管理工具，應以該工具取代上述 DPAPI 檔案流程。不要在已存在 Key 的安裝上重新產生 Key。

必要設定為 `CODEX_MONITOR_AES_KEY`、`CODEX_MONITOR_DRIVE_FILE_ID`、`CODEX_MONITOR_GOOGLE_CLIENT_ID`、`CODEX_MONITOR_GOOGLE_CLIENT_SECRET`。可選設定為 `CODEX_MONITOR_GOOGLE_SCOPE`、`CODEX_MONITOR_GOOGLE_TOKEN_FILE`、`CODEX_MONITOR_CODEX_PATH`。預設 scope 是 `https://www.googleapis.com/auth/drive.file`，預設 token 檔名是 `google-token.json`，預設 Codex 命令是 `codex`。

### B-3. 首次發布

1. 確認 Codex CLI 可執行且已登入：

   ```powershell
   codex --version
   codex login status
   ```

2. 確認本節所需環境變數已設定，再執行：

   ```powershell
   go run .
   ```

3. 程式會先讀取 Codex 帳號與 rate limits，完成 JSON 正規化及加密。若指定的 token 檔尚不存在，才會啟動 Google OAuth Desktop App 流程。
4. 首次授權時，將 Collector 顯示的 Google 授權網址貼到本機系統瀏覽器，登入正確 Google 帳號並同意授權。回呼只監聽本機 loopback；流程最多等待五分鐘。
5. 授權成功後，Collector 將 token 寫入指定檔案，更新固定 Drive File ID，成功時記錄 `本輪執行成功`。

既有 token 會用於後續執行；access token 到期時程式會嘗試 refresh 並保存更新結果。若 token 檔內容損毀，程式會回報失敗，不會靜默覆寫該檔。

### B-4. OAuth scope 與檔案權限

預設使用 `drive.file`。若固定檔案拒絕更新，先檢查 File ID、檔案擁有者、OAuth App 授權與 Google 回傳的安全錯誤原因。不要把單一 403／404 直接當成唯一原因，也不要讓程式自動擴大 scope。

只有在確認較廣授權確有必要、且已獲權限負責人同意時，才設定：

```powershell
$env:CODEX_MONITOR_GOOGLE_SCOPE = 'https://www.googleapis.com/auth/drive'
```

scope 改變後需使用符合該 scope 的新 OAuth 授權與 token 檔；保留原 token 的副本，不要用新的 token 覆蓋舊設定來排錯。完整 scope 的讀寫範圍較廣，請依實際需求核准。

核准後的重新授權應同時設定新 token 路徑，避免覆蓋舊 scope 的 token：

```powershell
$env:CODEX_MONITOR_GOOGLE_SCOPE = 'https://www.googleapis.com/auth/drive'
$env:CODEX_MONITOR_GOOGLE_TOKEN_FILE = Join-Path $env:LOCALAPPDATA 'CodexUsageMonitor-google-drive-token.json'
```

之後依 [B-3](#b-3-首次發布) 再執行 Collector，完成新的 OAuth 流程。

### B-5. 建置 Windows 執行檔（可選）

在 `collector/` 執行：

```powershell
.\scripts\build-win-x64.ps1
```

預期產物為 `collector/dist/codex-usage-monitor.exe`。先在目前 session 載入同一組 Collector 環境設定，再執行：

```powershell
.\dist\codex-usage-monitor.exe
```

### B-6. 驗證 HTTPS 發布檔案

測試 Client 只需要 AES Key，不需要 Google OAuth token。檔案 URL 必須是 HTTPS，且必須直接回傳 Binary；Google Drive 瀏覽頁 `/file/d/.../view` 不是 Binary 下載網址。使用 Drive metadata 的 `webContentLink`。

```powershell
go run . --test-url '<可直接下載 Binary 的 HTTPS URL>'
```

或使用封裝腳本：

```powershell
.\scripts\test-client.ps1 -Url '<可直接下載 Binary 的 HTTPS URL>'
```

若使用匿名下載，Google Drive 檔案必須允許知道連結的讀者存取。Client 會拒絕 HTTP、降級 redirect、無效或過大的 Binary、錯誤 Key、內容竄改、未知版本、無效 JSON 與缺少必要欄位。成功訊息會包含 schema version、快照時間及 limit 數量，不會顯示完整帳號 payload。

### B-7. 每次執行與資料更新

每次執行 `go run .` 或 Collector 執行檔會重新讀取一次最新 Codex 狀態，再用相同固定 File ID 更新完整加密 Binary。它不會保留歷史版本清單、建立新檔、刪除舊檔或自行依時間重試。若需要週期性更新，應由環境管理者另行建立排程；排程工作必須安全地取得與手動執行相同的 Codex 登入、AES Key、Google OAuth 設定及 token 檔路徑。

Key 若被更換，舊 Binary 仍使用舊 Key；使用新 Key 的 Client 無法解密舊檔。輪替 Key 時應安排 Collector 發布新 Binary，並同步更新授權 Client 使用的 Key。

### B-8. Collector 常見問題

| 現象 | 建議處理 |
|---|---|
| 顯示缺少環境變數 | 確認變數設定在啟動 `go run .` 的同一個 PowerShell 視窗；`.env.example` 不會自動載入。 |
| Codex account 或 rate-limit 讀取失敗 | 確認同一 Windows 使用者的官方 Codex 登入狀態與 `CODEX_MONITOR_CODEX_PATH`。Collector 不會代替使用者啟動 OpenAI 登入。 |
| Google OAuth 未完成 | 確認 Desktop App Client ID／Secret、授權 Google 帳號及本機 loopback 可用；首次 flow 最多等待五分鐘。 |
| Google Drive 回傳 403／404 | 檢查固定 File ID、擁有權、API 啟用狀態與 scope 授權。不要自動改用較廣 scope。 |
| token 檔無法讀寫 | 確認 token 目錄存在且目前 Windows 使用者有權限；token 檔應在 Repository 外。 |
| Client 回傳 HTTP 狀態錯誤 | 確認網址是可直接下載 Binary 的 HTTPS URL，且檔案可由目前下載方式讀取。 |
| Client 抱怨 Magic、GCM 或 JSON 無效 | 確認下載的不是 Google Drive HTML 瀏覽頁，Collector 已完成更新，且 Client 載入同一把 AES Key。 |
| 更換 AES Key 後無法讀取舊 Binary | 使用原 Key 驗證舊 Binary；或以新 Key 重新執行 Collector 更新檔案，再同步 Client Key。 |

OAuth Client Secret、token、AES Key 與原始憑證不應貼到 issue、聊天、公開 log 或 Git。Collector log 會限制原始 OAuth、Codex protocol 與 Google 錯誤內容，但分享前仍要檢查環境資訊及檔案路徑。
